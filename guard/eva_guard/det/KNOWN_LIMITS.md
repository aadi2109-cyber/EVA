# DET (content-side) — Known Limits

1. **T2 is a small lexical model** trained on ~200 authored sentences. It learns phrasing, not intent; novel wording, other languages, and obfuscation beyond T1's analysis-only decoders (base64/URL/ROT13/leet) can evade it. Rules supply a large share of recall.
2. **Reported accuracy is optimistic.** `test` attacks are near-variants of `train` items. The paraphrase challenge set (first run R 65% / FPR 15%) is a better indicator of generalization, and has since been used to add rules.
3. **False positives exist** on benign sentences that resemble attack phrasing (e.g. "Our system prompt guidelines say…", 2/20 benign on the challenge set). Cost is a removed sentence, not a blocked document.
4. **Sentence-level only.** Attacks split across sentences or fields, or carried by images/attachments/non-text content, are not seen. Cross-field context is limited.
5. **T3 (LAYA) is advisory and only thinly validated.** The adapter now uses the real `laya` API (earlier versions silently failed against it) and was exercised against the real English checkpoint, but the gray band in dev/challenge contains only 5-9 sentences, thresholds `0.80/0.30` are uncalibrated, warm latency is ~0.7-0.9 s/sentence on 2 CPU threads, cold load 11-24 s (preloaded in the background), RSS ~2.9 GB. It misses plain imperatives and flags quoted attacks. Not installed by default: see `T3_LOCAL_SETUP.md`. Without it `health().t3_available` is false and gray-band sentences are judged by T2 alone.
6. **Quoted/meta handling is a trade-off.** An attack wrapped in academic-sounding framing can be kept as "meta discussion" (audited, not removed). Authority still comes only from the gateway (SEC-2); DET never grants permissions.
7. **Over-cap bodies** (> `max_field_chars`, 1 MB) are truncated before scanning; content past the cap is not inspected.
8. **No adaptive-attacker evaluation.** Nothing here was tested against an attacker who can query the detector.
9. **Out-of-distribution text.** On AgentDojo's benign slot values (`python -m eval.det.agentdojo_bench`, untuned) DET flagged 12/29 (41%), including harmless reviews such as "Efficient and friendly service" and "Staff was attentive and always ready to help": the TF-IDF model scores short, unfamiliar sentences above the 0.60 block threshold. Detection of AgentDojo injection text (any sentence removed) was 130/175 (74%), but that overstates protection: by the stricter payload metric (no email/URL/IBAN/id/quoted string of the goal survives) only 80/130 (61.5%) were neutralised: injecagent 92%, other templates 54%; `ignore_previous` was 100% on the loose metric but 54% on the strict one, because the instruction text often survives while only part of it is cut. Loose-metric detail: 100% for `ignore_previous`/`injecagent`, 57% for `direct`, `system_message` and `important_instructions` because those wrap plain imperative tasks ("Delete the file with ID '13'…") that look like legitimate requests. DET alone cannot separate those from user intent; that is the job of provenance + SEC-2's gateway/task policy. This is not the AgentDojo benchmark proper (no agent, no utility/attack-success numbers).
10. **Structured tool output (found by AgentDojo workspace run).** On YAML tool results (calendar/email/drive) EVA sanitized 1,818 of 1,924 tool results (94.5%): bare lines such as `- name@domain.com` score ~0.9 because the T2 model treats `com`/`org`/`net` as attack tokens. Utility fell from 83% to 61% with no change in attack success (3.0% vs 2.9%). The scanner needs structure-aware handling of bare identifier/`key: value` lines before it is usable on such tools.
