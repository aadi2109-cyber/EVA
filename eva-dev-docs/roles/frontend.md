Types come from `contracts/ts/` (generated by SEC-2); until it exists, hand-write `src/api/types.ts` from doc 02 and replace later.

## What to build

**Screens**
1. **Login** — email/password → JWT; role from `/api/me`.
2. **Task workspace (main)** — chat input and message stream; streaming assistant text (`model.delta`); a step list (`plan.step`); a collapsible **tool call card** per call showing tool, args, who supplied each arg (`arg_sources`), the guard decision badge, and the (sanitized) output; final answer; task summary line ("1 sentence removed · 1 action denied · 1 approval").
3. **Live security trace panel** (side/bottom, toggleable) — chronological `guard.scan`, `guard.decision`, `state.verified`, `health.degraded`, `guard.error` with colour-coded, accessible badges: PASS, SANITIZED, QUARANTINED, HELD, ALLOW, REQUIRE_APPROVAL, DENY. Clicking an item shows reasons and reason codes (never raw flagged text; the BE does not send it).
4. **Approval modal** — shows the **exact action** (`ApprovalRequest.exact_action`), each arg with its source, why approval is required (reasons), expiry; actions: Approve / Deny / Edit. Editing args voids the approval and shows the new approval request (`re_approval_required`). Disable Approve while the modal's `action_hash` does not match the latest request.
5. **Degraded banner** — persistent when `health.degraded` or `/api/health` shows `tier2_available=false`; states the failure mode and what that blocks ("side-effect tools are disabled").
6. **Connectors** — Gmail card: status, mode (real/mock), connected account, scopes in plain words, Connect / Reconnect / Disconnect; clear "reconnect needed" state (Testing-mode tokens expire in ~7 days). Also shows Files workspace and Messages (mock) as connected.
7. **Files** — read-only tree + viewer of the workspace.
8. **History** — past tasks with outcome and summary; open a past task to replay its stored events.
9. **Admin (role=admin only)** — Health (guard health, tier-2 state, p50/p95), Audit explorer (filters by task/tool/decision, hash-chain verify button), Review queue (read, record decision), Config (view; proposals + second-admin approval UI), Kill switch (per tool / template / all write tools), Eval (read-only list of runs and metrics table). If time is short build Health + Audit first; the rest can be read-only.

**Behaviours**
- SSE with auto-reconnect and `Last-Event-ID` resume; ordering by `seq`; idempotent rendering.
- Treat all text from tools/emails/web as **plain text**: never `dangerouslySetInnerHTML`, never auto-link-and-fetch, no markdown image loading from untrusted content (blocks beacon exfiltration). Assistant markdown is rendered with a sanitizing renderer with images disabled.
- Show degradation and errors honestly; never hide a `guard.error` or `held` task.
- Empty, loading, and error states for every screen; keyboard navigable; contrast AA; responsive down to tablet.
- No secrets in the bundle. API base URL from `VITE_API_BASE`.

- `pnpm install && pnpm dev` works; `pnpm test` and `pnpm lint` pass.
- Demo scenarios S1, S2, S4, S7 are visible and understandable to a non-technical viewer.
- Matches `UI_NOTES.md` and the reference.
- Section in `coordination/STATUS.md` current. Requests to BE/SEC-2 go through `coordination/requests/`.

## Do not
- Do not decide security outcomes in the UI (no client-side "is this safe").
- Do not render raw flagged content, even if it somehow arrives; render the sanitized field only.
- Do not call the guard service directly; only the BE API (`/api/*`).
